## 未実装

| 項目 | 現状 | 必要な判断・作業 |
|---|---|---|
| メールの実送信 | キューに記録するだけ（`MAIL_TRANSPORT=none`）。画面にも「送信されていません」と表示 | 送信サービスの選定・契約（有料の可能性）、送信元ドメインの設定、運営の承認 |
| 成功報酬の請求・決済 | 内部記録のみ | 料率・基準額・請求時期・返金・未払いの方針（経営判断） |
| 緊急時の運営による取り次ぎ | 画面で「準備中」と案内し、通報フォームを案内 | 運営体制（受付時間・連絡手段）の決定 |
| 簡易発注書 | 設計のみ（`docs/simple-order-design.md`） | 法務確認、正式運用の可否 |
| アップロードファイルの保存時暗号化 | 契約書・写真は暗号化されていない（アクセス制御のみ） | ホスティングのディスク暗号化で足りるかの判断。不足ならアプリ層での暗号化を実装 |
| アカウント削除・データ削除請求 | 画面・手順なし | 個人情報の保存期間・削除方針（法務） |
| 複数サーバー間のリアルタイム通知 | 通知・チャットの即時反映は同じプロセス内だけ。別プロセスの更新は再読み込みで反映 | 複数台で運用する場合は共有の配信基盤が必要 |
| 実機テスト | 未実施 | `docs/device-test-procedure.md` に沿って実施 |

## 要判断（経営・法務）

- 「契約成立」の表示文言（法務レビュー前のため確定しない）
- 現地調査の住所の表示期限（仮：訪問日+7日）、契約後の連絡先の表示期限（仮：工事完了+90日）
- 成功報酬の料率・基準額（税込／税抜）・請求時期・キャンセル時の扱い
- 会社の代表電話の公開可否（現在は非公開）
- 既存の「工事中」「完了」案件（契約記録なし）の個別レビューの進め方
- AIの返信下書き（既定オフ。`AI_DRAFT_ENABLED=true` の時だけ、伏せ字にした会話を外部API（Anthropic）に送る）を将来使うか
