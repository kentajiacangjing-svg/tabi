# 公開準備状況（release readiness）— 2026-10-21 更新

「実装済み」は、コードと自動テストで確認できたものだけです。公開環境（ホスティング）と実機では **まだ何も検証していません**（環境がまだないため）。旧 `status-inventory.md` の内容はこの文書に統合しました。

## アップロードとファイルの点検結果
- 認可：写真・添付・契約書は、表示のたびにログインと権限を確認（他社・他の顧客・未ログインは404。テスト済み）。ファイルIDは推測できない乱数
- URLの期限：署名付きURLは使わず、毎回セッションで確認するため「期限切れURLの流出」はない。ブラウザ・中継サーバーには保存させない（`no-store`）
- 種類の確認：拡張子やブラウザの申告ではなく、ファイルの先頭のバイト列で JPEG/PNG/WebP/GIF/HEIC/PDF だけを受け付ける。返す時は `X-Content-Type-Options: nosniff` と、スクリプトを動かさない CSP（`sandbox`）
- サイズ：1ファイル10MBまで（ブラウザでも選択時に確認）
- **ウイルス対策：なし（P2）**。PDF・画像を他の利用者が開く。対策案：アップロード時に ClamAV 等で検査する（サーバーに検査ソフトが必要。ホスティング決定後に判断）
- **保存時暗号化：アプリ側ではなし（P2）**。ホスティングのディスク暗号化に依存（要確認）
- エラー時：画面には一般的なメッセージだけを出し、サーバーのログにも入力内容は出さない

## DB を直接操作した時の記録
- 運営画面からの操作は「監査ログ」に残ります。それに加えて、**DBファイルを直接開いて変更した場合も**、契約・契約履歴・成功報酬・利用者の権限と状態・会社の状態の変更は、DBのトリガーで `db_audit` に記録されます（個人情報は記録しません）。`db_audit` 自体は SQL で変更・削除できません
- 限界：DBファイルを丸ごと差し替えたり、トリガーを削除したりする操作は防げません。Render の「Shell」の利用者を最小限にし、利用した日時を運用記録に残してください
