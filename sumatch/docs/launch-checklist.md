# 本番公開前チェックリスト（launch checklist）

> 現在の判断：**一般向けの本番公開は NO-GO**。実ユーザーでの限定テストも、下の「実ユーザー限定テストの開始条件」がそろうまでは開始しません（それまではダミーデータでの内部テストのみ）。根拠は [release-readiness.md](./release-readiness.md)。
> 🔒 印は **持ち主の承認が必要な操作** です。承認なしには実行しません。

## A. 内部テスト（ダミーデータのみ）の開始条件 — すべて満たしている

- [x] デモモードとテスト用DBが本番と分かれている（`DEMO_MODE`、`STORAGE_DIR`）
- [x] 自動テスト（単体・複数プロセス・E2E 3サーバー）が合格
- [x] 実データを使わない（デモ・ダミーのみ）

## B. 実ユーザー限定テストの開始条件

### 環境（持ち主が設定。値はチャットやリポジトリに書かない）
- [ ] 🔒 ホスティングを決める（永続ディスク、HTTPS、ディスク暗号化、バックアップの可否を確認し、根拠を記録）
- [ ] `DEMO_MODE` を設定しない（本番ビルドでは既定でオフ）
- [ ] `DATA_ENCRYPTION_KEY` をシークレットに設定し、控えをバックアップと別の場所に保管
- [ ] `ADMIN_EMAIL` / `ADMIN_PASSWORD`（12文字以上）をシークレットに設定 → 初回起動後に運営でログインできることを確認 → `ADMIN_PASSWORD` を外す
- [ ] `APP_URL` を https の公開URLに設定（Cookie に Secure が付く）
- [ ] `CRON_SECRET` を設定し、外部スケジューラから `/api/cron/purge`（1日1回以上）・`/api/cron/reminders`（1日1回）を呼ぶ（期限切れデータの消去はサーバー内でも1時間ごとに動く）
- [ ] `MAIL_TRANSPORT` と `AI_DRAFT_ENABLED` は設定しない（メール送信なし、AI下書きなし）
- [ ] リバースプロキシで `X-Forwarded-For` を上書き設定（ログイン回数制限が正しく働くため）、HSTS を設定
- [ ] 監視：`/api/health` を外部の監視サービスから見る

### データと運用
- [ ] 本番DBは空から作る（デモデータを入れない）。`npm run db:inspect` で実データ・デモデータの件数を確認
- [ ] 毎日のバックアップ（`npm run db:backup`）と、別環境への復元訓練（`npm run db:restore -- <フォルダ> --yes`）を1回実施
- [ ] 運営の担当者：通報・要確認リスト・退会申請を確認する人と頻度（[limited-beta-runbook.md](./limited-beta-runbook.md)）
- [ ] 実機テスト（[device-test-procedure.md](./device-test-procedure.md)）を iPhone Safari・Android Chrome で実施し、証跡を記録

### 文書と同意（法務確認が必要）
- [ ] 利用規約・プライバシーポリシー（テスト用）の作成と、登録時の同意取得の実装
- [ ] 参加者への書面説明：テスト運用であること、SUMATCHの記録は工事請負契約書の代わりにならないこと、連絡先の自動判定と誤判定の報告方法、緊急時の扱い
- [ ] 参加する施工会社の確認（建設業許可など、どこまで確認するか）

## C. 一般公開の追加条件
- [ ] [法務チェックリスト](./legal-review-checklist.md) の確認完了と反映
- [ ] 🔒 メール送信サービスの契約・ドメイン認証（SPF/DKIM/DMARC）・テスト送信（[notifications.md](./notifications.md)）
- [ ] 🔒 成功報酬の料率・算定基準・請求方法の決定と、請求の実装（現在は試算のみ）
- [ ] 退会・データ削除の処理（現在は申請の受付のみ）と、データ項目ごとの保存期間
- [ ] 緊急時の運営対応（受付時間・連絡手段）が整い、画面に表示
- [ ] 負荷試験。複数台構成にする場合はリアルタイム通知の共有基盤
- [ ] 限定テストの振り返り（問い合わせ・誤判定・離脱）の反映
- [ ] 🔒 本番デプロイ、ドメイン設定、公開の最終承認（GO/NO-GO 判定を添えて）

## D. 公開当日〜公開後
- [ ] デプロイ前のバックアップ → デプロイ → `/api/health` → 主要フローの手動確認（お客様1件・施工会社1件）
- [ ] 問題があれば直前のバージョンに戻し（ロールバック）、DBはデプロイ前のバックアップから復元
- [ ] 1週間はエラーログと通報を毎日確認

## 決定済みの方針（2026-10-21）と当初の論点
- 契約前は全チャネルで連絡先禁止。現地調査は予約フロー＋お客様の同意で住所だけ開示。緊急時は運営経由（取り次ぎは準備中と表示）。代表電話は非公開。契約成立後は専用欄でのみ交換
- 当初の論点（記録）：現地調査当日の即時連絡、契約前の住所、会社情報の公開範囲、緊急時、契約後のチャット、契約書のない小規模工事 → 上記方針と [simple-order-design.md](./simple-order-design.md) で整理済み
