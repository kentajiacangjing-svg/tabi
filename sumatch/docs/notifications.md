# 通知の仕様（テスト運用版）

## チャネル

| チャネル | 状態 |
|---|---|
| アプリ内通知（ベルのマーク） | 実装済み |
| ブラウザ通知（許可した人だけ） | 実装済み。同じサーバープロセス内の更新のみ即時 |
| メール | **送信キューに記録するだけで、送信していません**（`MAIL_TRANSPORT=none`）。設定画面に「現在メールは送信されていません」と表示 |

## 通知するできごと

| できごと | 受け取る人 | メール対象 |
|---|---|---|
| 新しい相談（候補になった） | 施工会社 | ○ |
| マッチ成立 | お客様・施工会社 | ○ |
| 新しいメッセージ | 相手 | ×（アプリ内のみ。件数が多いため） |
| 見積の提出 | お客様 | ○ |
| 見積の改訂 | お客様 | ○ |
| 現地調査の候補日・日時決定・取り消し | 相手 | ○（本文に住所を含めない） |
| 依頼先に選ばれた／他社に決まった | 施工会社 | ○ |
| 契約条件の提示・更新・同意 | 相手 | ○ |
| 契約書の登録・確認・契約成立 | 相手／双方 | ○ |
| 連絡先の登録 | 相手 | ○（本文に連絡先を含めない） |
| 見積期限のリマインド | 施工会社 | ○ |

## メールのルール

- **本文に入れないもの**：メッセージ本文、電話番号・メールアドレス・住所、契約条件の全文。件名・短い説明・SUMATCHへのリンクだけ
- **重複防止**：同じ人への同じ通知（種類・件名・リンク）は、同じ1分間なら1通だけ（DBの一意制約）。二重タップ・再試行・複数プロセスでも重複しない
- **送信の流れ**：送信待ち → 送信中 → 送信済み／失敗（再試行）／停止
  - 失敗時は 2, 4, 8, 16 分…（最大60分）の間隔で再試行し、5回で打ち切り。運営が管理画面から再送の状態に戻せる
  - 送信中のまま10分たったもの（プロセスの停止など）は失敗として再試行
  - キューに入った後に本人がメール通知をオフにした場合は送らない（停止）
- **送信処理の起動**：`POST /api/cron/deliver-mail`（`CRON_SECRET` 必須）を外部のスケジューラから定期的に呼ぶ
- **開発・検証**：`MAIL_TRANSPORT=mock` で `STORAGE_DIR/mail-sandbox.jsonl` に書き出す（実在の宛先には送らない）

## 実送信を始める前に（要承認）

1. 送信サービス（SMTP／メール送信API）の選定と契約。有料の場合は経営判断
2. 送信元ドメインの SPF・DKIM・DMARC 設定
3. `lib/mailer.ts` に送信処理を追加し、テスト用の宛先（サンドボックス）で確認
4. 配信停止の導線（設定画面のメール通知オフ）の文言確認
5. 運営の承認後に `MAIL_TRANSPORT` を切り替え
