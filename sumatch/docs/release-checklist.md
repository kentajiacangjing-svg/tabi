# 本番公開前チェックリスト

> 現在の判断：**一般向けの本番公開は保留**（法務確認未完了）。限定テストは下の「限定テスト開始前」を満たせば可。

## 限定テスト開始前

- [ ] `DEMO_MODE` を設定しない（または `false`）。公開画面にサンプル会社・デモログイン・「デモ」表示が出ないことを確認
- [ ] `ADMIN_EMAIL` / `ADMIN_PASSWORD` をホスティングのシークレットに設定し、運営でログインできることを確認
- [ ] `DATA_ENCRYPTION_KEY`（`openssl rand -base64 32`）をシークレットに設定し、バックアップとは別の場所に控えを保管（なくすと連絡先・住所が読めなくなる）
- [ ] `MAIL_TRANSPORT` は未設定のまま（メールは送らない）。設定画面に「メールは送信されていません」と出ることを確認
- [ ] `ANTHROPIC_API_KEY` は、AI下書きを使うと決めた場合だけ設定（会話の内容が外部APIに送られる）
- [ ] ホスティングのディスク暗号化・HTTPS（HSTS）を確認
- [ ] `APP_URL` を https の公開URLにする（Cookie に Secure が付く）
- [ ] 永続ディスク上に `STORAGE_DIR` を置く（SQLite とアップロード）
- [ ] `npm run db:backup` が動き、`npm run db:restore`（確認のみ）でマニフェストが読めることを確認。定期バックアップの仕組みを用意
- [ ] 参加者（お客様・施工会社）に、テスト運用であること、SUMATCHの記録は工事請負契約書の代わりにならないことを書面で説明
- [ ] 施工会社に、契約書（工事請負契約書）を自社で作成し SUMATCH に登録する運用を説明
- [ ] 連絡先の自動判定・ブロックと誤判定の報告方法を参加者に説明。運営が通報を確認する担当と頻度を決める
- [ ] 下記「仕様の判断が必要な事項」の回答を反映

- [ ] 成功報酬・月額料金の請求方法（現在は記録のみで、請求・決済は未実装）
- [ ] 実データでのメール通知の送信設定（現在はメール送信ログへの記録のみで、実際の送信はしていない）
- [ ] 個人情報の保存方針：保存期間、削除手順（未実装）。連絡先・訪問先住所はアプリで暗号化済み。DBファイル全体・アップロード・バックアップの暗号化はホスティング側で確認

- [ ] 障害時の連絡体制と復元手順の訓練

## 仕様の判断が必要な事項（実装前に相談）

> 2026-10-21 の指示で、次のとおり方針を決定・実装済み：契約前は全チャネルで連絡先禁止、現地調査は「予約フロー＋お客様の同意で住所だけ開示」、緊急時は運営経由（取り次ぎ機能は準備中と表示）、代表電話は非公開のまま、契約成立後は専用欄でのみ交換。以下は当初の論点（記録として残す）。

契約前に直接の連絡が必要になりうるケース。現在はすべて **SUMATCH内のチャットで対応する前提** で、例外は実装していません。

1. **現地調査の日程・当日の連絡**：訪問時刻の調整は日時のやり取りでチャット内で可能。当日の遅刻・到着連絡など、即時の電話が必要な場面をどう扱うか
2. **現地調査の訪問先住所**：工事場所の住所は契約成立後の専用欄でしか共有できない。現地調査（契約前）に住所が必要な場合の扱い（例：現地調査の予約時だけ住所を共有する専用フォーム）
3. **施工会社の会社情報**：会社の代表電話・所在地・Webサイトを、契約前に会社ページで公開してよいか（現在は非公開）
4. **緊急時**：雨漏りなど緊急の工事で、すぐ電話したいお客様への対応
5. **契約成立後のチャット**：現在は契約成立後もチャットでの連絡先送信は禁止（専用欄を使う）。成立後はチャットでも許可するか
6. **契約書のない小規模工事**：エアコン取付など、工事請負契約書を作らない業種・金額の扱い（契約書の代わりに注文書・見積書の登録で良いか）
