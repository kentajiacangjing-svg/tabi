# 費用0円の限定デモ共有（ローカル＋Cloudflare Quick Tunnel）

> 状態（2026-10-22）：アプリ側の起動・アクセス制限は**この開発環境で検証済み**。Cloudflare Quick Tunnel とメール認証は、この環境から Cloudflare に接続できず `cloudflared` も入っていないため **未検証**（公式の告知・ドキュメントの記載にもとづく手順）。最初に共有する前に、下の「初回の確認」を行ってください。

## できること・できないこと

| | 内容 |
|---|---|
| 費用 | 0円（有料ホスティング・独自ドメイン・有料DB・Cloudflare アカウントのいずれも不要） |
| 構成 | 自分のPCで Next.js（`next start`）＋ SQLite をそのまま動かし、Cloudflare の Quick Tunnel で一時的な https URL を発行 |
| 扱うデータ | **サンプル（架空）データのみ**。デモモード固定。実際の個人情報・契約書・決済は扱わない |
| 向いている用途 | 数名の関係者に画面と流れを見てもらう、短時間のデモ |
| 向いていない用途 | 実ユーザーでの限定テスト・本番（URLが毎回変わる、稼働保証なし、PCを閉じると止まる） |

Quick Tunnel の制約（Cloudflare の公式ドキュメントより）：稼働保証（SLA）なし／同時処理は200リクエストまで（超えると429）／Server-Sent Events 非対応／URLは起動のたびに変わる。

## アクセス制限（3段）

1. **Cloudflare のメール認証（任意・推奨）**：`cloudflared` 2026.9.3 以降の `--allowed-mail` で、許可したメールアドレスの人だけが、届いたワンタイムPINを入力して入れる。運営者も閲覧者も Cloudflare アカウント不要（2026-10-02 の Cloudflare の告知による。**この環境では未検証**）
2. **サイト全体のパスワード（必須）**：`SITE_BASIC_AUTH`。未設定・12文字未満・デモ用パスワードの流用では起動しない
3. **アプリのログイン**：デモアカウント（パスワードは画面に表示されている公開値。上の2段が実質の鍵）

加えて、`noindex` ヘッダー、アプリは `127.0.0.1` だけで待ち受け（同じネットワークの他の機器からも直接は入れない）。

## 起動方法

前提：Node.js 22.5 以上、`sumatch/` で `npm ci` 済み。

```bash
cd sumatch
npm run build

# ターミナル1：アプリ（サンプルデータ専用の保存先 ./storage-demo）
SITE_BASIC_AUTH='参加者に伝えるユーザー名:12文字以上のパスワード' \
TUNNEL_ALLOWED_EMAILS='参加者1@example.com,参加者2@example.com' \
npm run demo:share
```

- パスワードはパスワード管理ツールで作り、シェルの履歴に残したくない場合は `read -s` などで変数に入れてから渡す。チャット・リポジトリには書かない
- `demo:share` が自動で設定するもの：`DEMO_MODE=true`、`MAIL_TRANSPORT=none`、`ROBOTS_NOINDEX=true`、`STORAGE_DIR=./storage-demo`（指定がなければ）、`CLIENT_IP_HEADER=cf-connecting-ip`、`REALTIME_STREAM=off`。`ANTHROPIC_API_KEY`・`AI_DRAFT_ENABLED`・`ADMIN_EMAIL/PASSWORD` はアプリに渡さない
- データベースにサンプル以外のアカウント（参加者がデモ中に登録したもの等）があると、確認を求めて止まる。架空の情報だけと確認できたら `--allow-test-accounts` を付ける（`npm run demo:share -- --allow-test-accounts`）

## 接続URLの取得（ここで外部に公開されます）

ターミナル1に表示されたコマンドを、内容を確認してから **ターミナル2** で実行します。

```bash
# cloudflared のインストール（無料・アカウント不要）：公式の手順に従う。例 macOS: brew install cloudflared
cloudflared --version            # 2026.9.3 以降であること（メール認証を使う場合）
cloudflared tunnel --url http://127.0.0.1:3100 --allowed-mail '参加者1@example.com'
```

- 出力の中の `https://〜.trycloudflare.com` が接続URL。このURLとサイトのパスワードを、**別々の経路で**参加者に伝える
- 止める：ターミナル2で Ctrl+C（URLは即座に無効）→ ターミナル1で Ctrl+C
- 再起動するとURLは変わる（前のURLは使えなくなる）

## 初回の確認（未検証の項目）

| # | 確認すること | 期待 |
|---|---|---|
| 1 | パスワードなしで接続URLを開く | メール認証の画面（設定時）→ その後サイトのパスワード入力 |
| 2 | 許可していないメールアドレスでPINを要求 | 入れない |
| 3 | デモアカウントでログイン → チャット送信 | 相手側に20秒以内に表示（リアルタイム配信は切っているため、ポーリングで更新） |
| 4 | ログインを数回失敗 | 回数制限が接続元ごとに働く（`cf-connecting-ip` で判定） |
| 5 | `curl -sI <URL>` | `x-robots-tag: noindex` |

結果を記録してから参加者に共有してください。1・2がうまくいかない時は、メール認証なし（サイトのパスワードのみ）で使うかを判断してください。

## 安全上の注意

- **架空の情報だけ**：画面にも「実在の個人情報は入力しないでください」と表示。写真・契約書のアップロードも、サンプル画像・ダミーPDFだけを使う
- デモ用ログインは公開値なので、**サイトのパスワードとメール認証が実質の鍵**。URLとパスワードを同じメッセージで送らない
- デモでは運営アカウント（管理画面）にも入れる。表示されるのはサンプルデータのみ
- 共有中はPCをスリープさせない。共有が終わったらトンネルを止める。URLを知っている人は、トンネルが動いている間アクセスを試せる
- データは自分のPCの `./storage-demo` にだけ残る。終わったら `STORAGE_DIR=./storage-demo npm run db:inspect` で中身を確認し、不要なら `npm run db:reset` で初期化（実データがあると止まる）
- メールは送信されない（キューに積むだけ）。AI下書きは動かない。課金の発生する外部サービスは使わない
- 本番用の `./storage` や本番の鍵・パスワードを、このデモに使わない

## Cloudflare Access（アカウントありの Zero Trust）を使う場合

Quick Tunnel ではなく、Cloudflare アカウントの名前付きトンネル＋Access のポリシーにする方法もある（無料プランあり）。ただし、**アカウント登録が必要**で、アプリのURLを Cloudflare 上のドメインに置く構成が一般的（独自ドメインが必要になる可能性。要確認）。今回の「独自ドメインなし」の条件に合わないため実施していない。進める場合は、登録の前に確認をお願いします。
