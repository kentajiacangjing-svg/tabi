# 簡易発注書フロー（設計のみ・正式運用は法務確認まで保留）

エアコン取付など、工事請負契約書を別途作らない小規模工事向けに、SUMATCH上で「簡易発注書」を作り、双方が承認する流れ。**未実装**（法定記載事項の確認後に実装する）。

## 方針

- **金額だけで必須項目を省略しない**：小規模でも、下記の必須項目はすべて必要
- 「契約成立」の判定は、通常の契約書と同じ仕組み（文書のハッシュに対する双方の確認）を使う。簡易発注書は、契約書ファイルの代わりにシステムが作る文書として扱う
- 簡易発注書を使える条件（工事種別・金額の上限など）は、法務確認後に決める

## 必須項目

| 項目 | 入力者 | 内容 |
|---|---|---|
| 作業範囲 | 施工会社 | 何を・どこまで（例：エアコン1台の取付、配管4mまで） |
| 金額（税込）と内訳 | 見積から自動 | 見積の版番号を記録。**見積の合計と一致しない場合は作成できない** |
| 追加費用の条件 | 施工会社 | 例：配管延長 1mあたり○円、事前に承認を得てから |
| 作業日・所要時間 | 施工会社（お客様が承認） | |
| 施工場所 | お客様 | 暗号化して保存（現地調査の住所と同じ扱い） |
| 当事者情報 | 自動＋入力 | 会社名・建設業許可（該当する場合）・担当者、お客様の氏名 |
| キャンセル・変更の条件 | 施工会社 | 時期と費用 |
| 支払条件 | 施工会社 | 時期・方法 |
| 保証・トラブル時の対応 | 施工会社 | 保証期間・対象、連絡方法（SUMATCH経由） |
| 承認の記録 | 自動 | 双方の承認日時・承認した版（ハッシュ） |

## 流れ

1. 契約条件に双方が同意（既存の流れ）
2. 施工会社が「簡易発注書を作る」を選び、不足項目を入力 → システムが文書（PDFまたは固定のHTML）を生成し、ハッシュを記録
3. 生成前の検証：必須項目がすべて入力されている、金額が最新の見積の合計と一致する、見積が最新版である
4. お客様が文書を確認して承認 → 施工会社も承認 → 「契約成立」（既存の確認処理と同じ）
5. 内容の変更は新しい版を作り、承認はやり直し

## 法務に確認すること

- 建設業法第19条の書面の記載事項を、この項目で満たせるか（軽微な工事の扱いを含む）
- 電子で交付する場合の要件（相手方の承諾、改変の防止、見読性）
- 特定商取引法が関係するケース（訪問しての契約など）
