# データ運用手順（バックアップ・復元・デモデータ）

すべて `STORAGE_DIR`（既定 `./storage`）を対象にします。本番環境で実行する時は、実行前に必ず担当者の承認を取ってください。

## サンプルデータと実データの区別

- デモ用の初期データで作られたアカウント・会社には `is_demo = 1` が付きます
- この列がなかった古いデータベースでは、起動時に **デモ用の固定アドレス（`@demo.sumatch.jp` と `@<会社>.demo`）だけ** に印を付けます。それ以外のデータ（契約状態・金額・履歴など）は変更しません
- `DEMO_MODE` がオフの時、`is_demo = 1` の会社は公開画面・会社検索・会社ページに出ず、`is_demo = 1` のアカウントはログインできません（既存のログインも無効になります）

## 点検（読み取り専用）

```bash
STORAGE_DIR=./storage npm run db:inspect
```

デモ／実データのアカウント数、実データのお客様の相談・契約の件数、契約の状態別件数を表示します。`hasRealData: true` の時は、初期化・復元の前に必ずバックアップしてください。

## バックアップ

```bash
STORAGE_DIR=./storage npm run db:backup -- ラベル
```

- `backups/<日時>-<ラベル>/` に `sumatch.db`（`VACUUM INTO` による一貫したコピー）・`uploads/`・`manifest.json`（ハッシュ値と件数）を保存します
- アプリを止めずに実行できます。元のデータは変更しません
- 保存先は `BACKUP_DIR` で変えられます。バックアップには個人情報が含まれるため、アクセスできる人を限定してください

## 復元

```bash
# 1. アプリを停止する
# 2. 内容の確認（何も変更しない）
STORAGE_DIR=./storage npm run db:restore -- backups/<フォルダ>
# 3. 実行（現在のデータは自動で backups/<日時>-before-restore に退避）
STORAGE_DIR=./storage npm run db:restore -- backups/<フォルダ> --yes
# 4. アプリを起動する
```

マニフェストのハッシュ値と一致しないバックアップ（破損・改変）は復元しません。

## デモデータの初期化

```bash
STORAGE_DIR=./storage npm run db:reset            # 内容の表示だけ
STORAGE_DIR=./storage npm run db:reset -- --yes   # 実行（先に自動バックアップ）
```

- 実データ（デモ以外のアカウント・相談）があると **中止します**。本番環境の初期化には使えません
- 既定の動作（起動時など）でデータを自動削除することはありません
- 初期化後の次回起動で、`DEMO_MODE` に応じた初期データが作られます（オン：サンプル一式、オフ：カテゴリ・地域・料金プランのみ）

## 運営アカウント

デモモードでない環境では、サンプルの運営アカウントはありません。最初の運営アカウントは環境変数で作ります（運営が1人もいない時だけ、1回だけ作成）。

```bash
ADMIN_EMAIL=ops@example.com ADMIN_PASSWORD='12文字以上のパスワード' npm start
```

- パスワードは環境変数（ホスティングのシークレット設定）で渡し、コード・リポジトリ・ログに書かないでください
- アカウント作成後は `ADMIN_PASSWORD` を環境から外して構いません

## 既存の契約データへの影響（今回の変更）

- 今回の変更前に「工事中」「完了」になっていた契約は「双方の合意確認済み」として表示されます。契約書の登録・確認の記録がないため **「契約成立」にはならず、専用の連絡先欄も開きません**
- 「工事中」の案件は、そのまま「工事が終わった」にできます
- 金額・状態・履歴は自動では変更しません。これらの案件を「契約成立」として扱うかどうかは、承認のうえ個別に判断してください
