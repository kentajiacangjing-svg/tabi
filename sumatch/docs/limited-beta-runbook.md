# 限定テスト運用手順（limited beta runbook）

> 実ユーザーでの限定テストは、[launch-checklist.md](./launch-checklist.md) の「B」がすべてそろってから始めます。それまでは、ダミーデータでの内部テストだけを行います。

## 1. テスト環境の準備（持ち主が行う）
1. ホスティングを用意し、永続ディスクと HTTPS を設定する。保存時暗号化とバックアップの仕様を確認し、メモに残す
2. シークレット（環境変数）を設定する：`DATA_ENCRYPTION_KEY`、`ADMIN_EMAIL`、`ADMIN_PASSWORD`、`APP_URL`、`CRON_SECRET`
   - 値はチャット・メール・リポジトリに書かない。ホスティングの「シークレット」設定画面にだけ入れる
   - `DATA_ENCRYPTION_KEY` は `openssl rand -base64 32` で作り、控えをパスワード管理ツールに保管する
3. `npm run build` → `npm start` で起動し、運営アカウントでログインできたら `ADMIN_PASSWORD` を外す
4. 外部スケジューラ（ホスティングのcron機能など）を設定：`/api/cron/purge` を毎日、`/api/cron/reminders` を毎日（`Authorization: Bearer <CRON_SECRET>`）
5. 監視サービスで `/api/health` を5分ごとに確認（止まったら担当者に通知）
6. 初回バックアップ：`npm run db:backup -- initial`

## 2. 参加者
- 協力企業・利用者の数、募集方法、本人確認の方法は **持ち主が決める**（未定）
- 参加前に書面で説明し、同意を得る：テスト運用であること／SUMATCHの記録は工事請負契約書の代わりにならないこと／連絡先は自動判定で送れないことがあり、誤判定は報告できること／緊急時の扱い／データの扱い（[privacy-inventory.md](./privacy-inventory.md) の説明文案、法務確認後）
- 施工会社には、契約書を自社で作成して SUMATCH に登録してもらう

## 3. テストの流れ（1件あたり）
1. お客様：相談の登録 → 会社を選んで相談
2. 施工会社：対応したい → メッセージ → 現地調査の候補日 → 見積
3. お客様：比較 → 依頼先に決める
4. 施工会社：契約条件 → 双方同意 → 契約書の登録 → 双方確認（契約成立）→ 連絡先の交換 → 工事開始・完了
5. 運営：成功報酬の試算を確認（請求はしない）

## 4. 運営の日次作業（担当者・時間帯は持ち主が決める）
- 管理画面「通報」：誤判定の報告・トラブルの確認
- 「成功報酬（試算）・要確認」：契約記録の足りない案件、止まっている案件、連絡先ブロック後に途絶えた会話（**兆候のみ。違反と断定しない**）
- 「退会申請」：内容を確認し、対応を記録（削除は手順と承認のうえで）
- 「監査ログ」：運営自身の閲覧記録を週1回確認
- バックアップが作られているか確認

## 5. 問い合わせ・緊急時
- 対応時間の案（平日10:00〜18:00）は **実際に対応できる体制ができるまで画面に表示しない**
- 現在の画面表示：「緊急時の運営による連絡の取り次ぎは準備中。チャットか、運営への通報からお知らせください」
- 通報を受けたら：担当者が確認 → 当事者にアプリ内で連絡 → 必要なら持ち主に報告
- 安全にかかわる緊急事態（漏水・火災など）は、利用者に 119・110・各インフラ会社への連絡を案内する文言を、法務確認のうえで用意する（未実装）

## 6. 障害時の連絡と停止手順
1. 監視が異常を知らせたら、担当者が `/api/health` と画面を確認
2. 個人情報の漏えいの疑いがある場合：**サービスを停止**（ホスティングで停止）→ 持ち主に即連絡 → 記録を保存（ログ・DBのバックアップ）→ 法務・個人情報保護の手続きは持ち主が判断
3. データの破損：アプリを停止 → `npm run db:restore -- backups/<直近> --yes`（現在のデータは自動で退避される）→ 起動 → `/api/health`
4. 変更による不具合：直前のバージョンに戻す（git のコミットを戻してデプロイ）
5. 参加者への連絡文（アプリ内のお知らせ）は持ち主が確認してから出す

## 7. 振り返り（週1回）
- 問い合わせ・通報の件数と内容、誤判定の例、途中でやめた箇所、所要時間
- 改善の候補を docs/release-readiness.md の課題に追加
