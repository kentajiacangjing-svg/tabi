# 成功報酬の状態遷移とテストケース（案）

> 現在は **試算の記録のみ**。請求・決済は行いません。以下の「取消・返金・契約変更・未払い」は **案** で、経営・法務・経理の決定前に実装しません。

## 現在の実装（rule_version draft-2）
```
契約成立 ──▶ 要確認（試算） ──▶ 確認済み（試算・請求前） ──▶ 請求済み（手動記録） ──▶ 入金確認（手動記録）
                 │   ▲                 │                         │
                 ▼   │（理由必須）        ▼                         ▼
               対象外 ─┘              対象外 / 要確認に戻す        対象外
```
- 記録は契約1件につき1件（DBの一意制約）。同時に契約成立しても重複しない（テスト済み）
- 算定：既定は税抜の契約金額 × プランの料率、1円未満切り捨て（設定で税込・四捨五入・切り上げに変更可。変更はこれからの記録だけに適用）
- 状態の変更は運営の手動記録のみ。変更ごとに記録（`fee_events`）

## 決定が必要な遷移（案）

| できごと | 案 | 決めること |
|---|---|---|
| 契約成立後のキャンセル（着工前） | 対象外にする（理由を記録） | キャンセル料が発生した場合に報酬の対象とするか |
| 工事中の中止 | 実施分の金額で再計算した新しい記録を作り、元の記録は対象外 | 算定の基準（実施分・支払われた額） |
| 契約金額の変更（追加工事・減額） | 変更契約ごとに差額の記録を追加（元の記録は変えない） | 追加工事を対象にするか、値引き・諸経費の扱い |
| 二重の契約（同じ案件で別会社） | 起きない（DBで1案件1契約）。運営の補完で起きた場合は片方を対象外 | — |
| 請求後の返金 | 「返金」状態を追加し、返金額と理由を記録 | 返金の条件 |
| 未払い | 支払期限を過ぎたら「督促中」 → 期限 → 「回収不能」 | 支払期限、督促の方法、サービス停止との関係 |
| 料率の変更（プラン変更） | 依頼先決定時点の料率を使う（現在の実装） | 変更のタイミングの規約上の扱い |

## テストケース
- 実装済み（`fees.test.ts`・`multiprocess.test.ts`）：契約成立で1件だけ記録／同時4プロセスでも1件／未成立の契約には記録なし／許されない遷移は拒否／対象外・差戻しは理由必須／変更履歴／設定変更は新しい記録だけに適用
- 決定後に追加：キャンセル（着工前・着工後）、金額変更（増額・減額）、返金、未払いの期限経過、プラン変更の前後、運営の補完による契約
