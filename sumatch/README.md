# SUMATCH（スマッチ）

探す・比べる・決めるを、ひとつに。

サービスを探している一般ユーザーと、仕事を受けたい企業をつなぐマッチングプラットフォームのMVPです。
相談 → マッチング → チャット → 見積もり → 比較 → 契約記録 までを、SUMATCHの中だけで完結できます。

## すぐに試す

```bash
cd sumatch
npm install
npm run dev          # http://localhost:3100
```

初回起動時に、デモデータ（企業10社・ユーザー5人・案件5件・見積もり・チャット・KPI）が自動で作られます。
`/login` の下にある「デモアカウントで試す」を開くと、各立場でワンクリックでログインできます（パスワードはすべて `sumatch123`）。

## デザインの考え方

「見る → 直感で選ぶ → 次へ進む」。機能を増やすのではなく、迷うものを消す方針で組み直しています。

- **1画面＝1つの質問**：トップは「どんな工事？」だけ。予算は？ → いつ頃？ → 場所は？ → この条件で探します、と1画面1問で進みます。質問は大きく、選択肢は大きなカード、「次へ」は常に画面下の同じ位置。進捗は上部の細いバーだけです。
- **会社は1社ずつ**：カードには施工写真・会社名・評価・口コミ件数・対応エリア・概算価格帯・得意分野・「詳しく見る」だけ。ボタンは「× 興味なし / ♡ 保存 / ✓ 相談したい」の3つ。スワイプ（左＝興味なし、右＝相談したい）とキーボード（← / → / S）にも対応しますが、ボタンだけで完結します。PCでは中央に最大540px、スマホでは画面幅の約92%で表示します。
- **マッチの瞬間**：施工写真を全面に、小さく「相談できます」、大きく「マッチしました」、その下に相手の名前。「メッセージを送る」と「あとで」だけで、紙吹雪などはありません。
- **会社詳細の順番**：写真 → 会社名・評価・エリア → 相談したい → 施工事例 → 得意な工事 → 価格帯 → 口コミ → 保証・資格 → 会社情報。
- **チャット**：上部は会社名・返信の目安・「会社詳細」だけ。見積は「見積が届きました ¥1,180,000 工期：約14日 見積を見る」というカードで届きます。電話番号・メール・LINEは表示しません。
- **見積比較**：上に「価格で選ぶ／安心で選ぶ／工期で選ぶ」の3つの視点（押すと並び順と強調が切り替わります）。各見積は 会社名・総額・工期・保証・評価 だけを大きく並べ、「最安」「安心」「最短」の小さなタグで違いを示します。材料・追加費用・支払い条件・担当者・有効期限は「詳細」を開いた時だけ表示します。
- **企業側**：ホームは「今日やること」（新しい相談・返信待ち・見積作成・契約）と、最優先の相談を大きく1件（お客様が希望している相談が先）、残りはコンパクトな一覧。相談は1件ずつ（場所・工事内容・予算・希望時期を大きく、「見送る / 対応したい」）。閲覧数・相談率・マッチ率・契約率・売上は `/business/analytics` にだけ置いています。
- **ナビ**：お客様は ホーム / 探す / メッセージ / 保存 / アカウント、企業は ホーム / 相談 / 案件 / メッセージ / 設定。
- **配色**：背景 `#F7F7F4`、カード `#FFFFFF`、文字 `#111111`、補助文字 `#666A66`、メイン `#184D3A`、セカンド `#2F6B55`、淡いグリーン `#E7F0EA`、境界線 `#E4E5E1`。暖色アクセント `#D97A4A` はマッチ・通知・重要なステータスだけ（画面の5%以下）。セクションごとに `#F7F7F4` / `#FFFFFF` / `#E7F0EA` を使い分け、白一色のページにしません。トークンは `src/app/globals.css` にあります。
- **写真が主役**：工事の種類はすべて写真カード。会社カードは上部の約6割が施工写真、マッチ画面は会社の施工写真を全面に敷きます。PCでは「写真＋質問」「カード＋条件・次の会社」「写真＋会社情報（固定）」の2カラムです。
- **強弱**：見出しは 600〜700、本文は 400〜500。金額・件数・評価は等幅数字で大きく。カードは角丸20〜28px、影は `0 12px 40px rgba(0,0,0,.06)` 程度。
- **動き**：画面遷移は0.22秒のフェード＋6px上昇（`top` を動かすので固定のタブバーやチャットに影響しません）、ボタンはホバーで1px浮き押すと0.98倍、カードはホバーで2px浮きます。マッチは拡大＋フェード＋ぼかし解除（0.7秒）。`prefers-reduced-motion` では止まります。
- **写真素材**：デモの施工写真（`public/seed/*.jpg`）は、ご提供いただいた写真を4:3で切り出したものです（文字・ロゴなし、車のエンブレムは消去済み）。元画像が約710×530pxのため、表示サイズはこれを超えないようにしています（マッチ画面の全面背景はぼかして使用）。実運用では各社が高解像度の実写を登録します。お客様の「現地写真」は `scripts/gen-seed-images.mjs` の素材写真のままです。
- **ブランド要素**：見出しの上に短いブランドコピー＋深緑の細いライン（`Kicker`）。カード角丸は24px（写真・会社カード・マッチは28px）、ボタンは高さ48/56px・角丸16px、写真は4:3（PCの会社カードのみ16:10）。アクティブ状態は小さな緑のドット。

## 主なページ

一般ユーザー: `/`（どんな工事？）→ `/diagnosis`（予算・時期・場所・確認）→ `/matches`（会社を1社ずつ）→ `/match/[id]`（マッチ）→ `/messages/[id]` → `/quotes`（比較）→ `/quotes/[id]`（見積詳細・決定）。ほかに `/saved` `/projects` `/projects/[id]` `/company/[id]` `/account` `/notifications`
企業: `/business` `/business/signup`（4ステップ）`/business/dashboard`（今日やること）`/business/analytics` `/business/leads`（相談を1件ずつ）`/business/leads/[id]` `/business/match/[id]` `/business/active`（案件）`/business/messages` `/business/quotes` `/business/quotes/new` `/business/profile`
運営: `/admin`（概要 / ユーザー / 企業 / 相談 / マッチ / 見積 / 契約 / 分析、ほかにチャット確認・通報・カテゴリ・地域・料金プラン・送信メール）。分析では 訪問 → 相談開始 → 相談完了 → 会社閲覧 → マッチ → 見積 → 契約 のファネルとCVRを表示します。

## 仕様のポイント

- **双方合意のマッチング**: お客様の「相談したい」（1つの相談につき最大3社）と、企業の「対応したい」の両方が揃った時だけメッセージが始まります。二重確認はありません。
- **紹介の順番**は対応地域・予算帯・カテゴリ実績・希望時期・口コミ・返信速度・自社施工から算出します（`src/lib/matching.ts`）。画面には数値ではなく「藤沢市に対応・予算が合う」のような理由だけを出します。料金プランや SUMATCH Web の利用有無は入力に含めていません。
- **連絡先交換の検知**: 電話番号・メールアドレス・LINE・QRコード・SNS・URL（全角数字や漢数字も含む）を送信前に検知して警告し、運営画面に記録します（`src/lib/contact-detect.ts`）。
- **見積もり**: 工事項目・数量・単価・諸経費・値引き・消費税・保証・工期・材料・支払条件・追加費用・備考・PDF添付。改訂すると版が上がり、比較画面は最新版を表示します。比較コメントは今はルールベースで、`compareQuotes()` を差し替えればAIコメントにできます。
- **契約記録とステータス**: 相談中 → 見積もり中 → 比較中 → 契約 → 工事中 → 完了。完了後は口コミを投稿できます。
- **通知**: アプリ内通知・ブラウザ通知（SSE）・メール。メールは送信キュー（`email_outbox`）に記録され、運営画面で確認できます。SMTP・LINE公式アカウント・LINE WORKS は `src/lib/notify.ts` に送信処理を足せば使えます（LINEは通知専用で、会話はSUMATCH内で行います）。見積もり期限のリマインドは `POST /api/cron/reminders`（`Authorization: Bearer $CRON_SECRET`）。
- **返信の下書き**: `ANTHROPIC_API_KEY` を設定すると、チャットの「その他 → 返信の下書きを作る」で Claude が下書きを作ります。未設定時はテンプレートで下書きします。送信は必ず本人が行います。
- **料金プラン・カテゴリ・地域**はDBで管理し、`/admin` から追加・変更できます。初期カテゴリは 外壁・屋根／キッチン／お風呂／内装（トップに表示）と、トイレ・洗面／外構・庭／エアコン／ハウスクリーニング（「その他」の中）、引越し・不用品回収（非公開）です。

## 技術構成

- Next.js 15（App Router, Server Actions）/ TypeScript / Tailwind CSS v4
- DB: SQLite（Node 22 の組み込み `node:sqlite`。ネイティブモジュール不要）。スキーマは `src/lib/db/schema.ts` にあり、TEXT主キー・ISO日時で書いているため Postgres / Supabase へ移しやすい形です
- 認証: メール＋パスワード（scrypt）、HttpOnly Cookie のセッション（DBにはトークンのハッシュのみ保存）。ロールは `customer` / `business` / `admin`
- リアルタイム: Server-Sent Events（`/api/stream`）＋ポーリングのフォールバック。複数サーバーで動かす場合は `src/lib/realtime.ts` を Supabase Realtime / Redis に差し替えます
- ファイル: `storage/uploads` に保存し、`/api/files/[id]` で権限チェックしてから配信。ファイル形式はマジックバイトで判定（JPEG/PNG/WebP/GIF/HEIC/PDF、10MBまで）。配信時は `Content-Security-Policy: sandbox` を付けます

### セキュリティ

- すべてのページ・Server Action・APIで、サーバー側でロールと所有者を確認しています（`src/lib/access.ts`）。middleware は未ログイン時の入口チェックだけです
- お客様は自分の相談だけ、企業は自社に届いた案件だけ、運営は全体を見られます。企業にはマッチ成立までお客様の名前を表示せず、連絡先は一切公開しません
- 入力値は zod で検証しています。秘密鍵（`ANTHROPIC_API_KEY` など）はサーバー側だけで使い、フロントには出しません

## テスト

```bash
npm test               # ユニットテスト（マッチ度・連絡先検知・相場・見積もり比較・マッチング成立）
npm run build && npm run test:e2e   # ブラウザで通しのフロー（相談 → マッチ → チャット → 見積もり → 比較 → 決定 → 管理画面）と権限チェック
```

## 本番運用での注意

- SQLite と `storage/` は永続ディスクが必要です（Vercel のようなサーバーレスでは保存できません）。Render / Fly.io / VPS などで `npm run build && npm start`、または DB を Supabase(Postgres) に移して運用してください
- 公開URLが https の場合は `APP_URL=https://...` を設定すると Cookie に `Secure` が付きます
- 実テストでは `DEMO_MODE=false` にして、デモ用のワンクリックログインを無効にしてください

## 今後の拡張（データ構造は対応済み）

電子契約・決済（Stripe Connect）・エスクロー・工事保証・進捗管理は `contracts` テーブルにぶら下げる想定です。企業の複数担当者は `company_members`（owner / staff）で管理しています。
