# 引き継ぎ：公開前に必要なこと・費用・制約

## 1. ご本人（事業者）にしかできない操作

APIキーや資格情報はチャットに貼らず、各サービスの管理画面・`supabase secrets set`・EAS の Secrets に直接入力してください。

1. **専門家への相談**: [法令確認チェックリスト](legal-checklist.md) の各論点（出会い系サイト規制法・東京都条例・風営法・資金決済法・職業安定法など）。必要な届出・許認可の判断
2. **Supabase**: アカウント・プロジェクト作成（東京リージョン推奨）、有料プランの契約判断、Auth のメール送信設定（独自ドメインの SMTP）
3. **Apple Developer Program / Google Play Console** の登録（法人名義推奨）、ストアの年齢レーティング・プライバシー申告
4. **決済**: 決済代行事業者（予約）とアプリ内課金（会員プラン、RevenueCat 等）の契約・加盟審査
5. **本人確認（eKYC）** 事業者との契約
6. **ドメイン・運営者情報**: 特定商取引法の表記、問い合わせ窓口、利用規約・プライバシーポリシー（弁護士確認版）
7. **正式名称・価格・ランク境界の決定**（管理画面「プラン・ランク・設定」から変更可能）

## 2. 決済の本番化（契約・審査完了後）

1. 会員プラン: RevenueCat（App Store / Google Play）を導入し、Webhook を `supabase/functions/payments-webhook` で受けて `membership_entitlements` を更新（署名検証・冪等化）
2. 予約: 決済代行の与信（承認時）→売上確定（完了時）→取消/返金を、現在のサンドボックス処理（`settle_booking_payment` / `process_refund`）と同じ状態遷移で実装
3. `payment_mode` を `live` に変更（変更は監査ログに記録。アダプター未設定のままでは予約確定がサーバーで拒否されます）
4. 女性への送金は、資金決済法・税務の整理と契約後に別途実装（現在は台帳まで）

## 4. 技術的な制約・未実装

- **本番決済・送金**: 未実装（サンドボックスのみ）。Webhook は雛形
- **本人確認**: 開発版は生年のテスト提出＋運営承認。eKYC 未連携
- **プッシュ通知**: アプリ内通知センターのみ（Expo Notifications 未導入）
- **Realtime**: Supabase 接続時は Realtime で新着を購読（RLS で当事者のみ配信）。ローカル開発サーバーは Realtime 非対応のためポーリング（3〜8秒）
- **ローカル開発サーバー**: Supabase のサブセット互換（Auth・RPC・最小 REST・Storage）。デモ・自動テスト専用で、インターネットに公開しないこと
- **実機テスト**: この開発環境には iOS シミュレータ / Android エミュレータ / 実機がないため未実施。代替として iOS・Android 向け JS バンドルの書き出し（Hermes バイトコード生成）成功と、Web（Chromium）での通し操作・6 画面幅の表示検証を実施
- **Supabase 本体での検証**: この環境では Supabase の Docker イメージを取得できなかったため、同一マイグレーションを PGlite（PostgreSQL 18 相当）と実 PostgreSQL 16 に適用して検証。`supabase start` での動作確認はご自身の環境で実施してください（README の手順）
- **フェーズ2**: 店舗予約・指名・ボトル注文は未実装（`bookings.kind`・`venue_references` で拡張余地を確保）。スカウト機能は実装していません
- **仮設定**: キャンセル規定（24時間前まで無料・以降 0%）、手数料率 20%、プラン価格、ランク境界、禁止語リスト

## 5. 法的・審査上の未解決点

- 事業がインターネット異性紹介事業・デートクラブ営業等に該当するか、該当する場合に必要な手続きと事業の成立可否
- 予約金額の決済をストア外で行えるか（対面サービスとして認められるか）、決済代行の加盟可否
- 女性への支払いスキーム（資金移動・源泉徴収）
- 年齢要件（20歳以上）の根拠と確認手段
- ストア審査で「夜職」「同伴」の文脈がどう評価されるか（事前相談推奨）
