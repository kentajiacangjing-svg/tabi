| 指示書の項目 | 検証内容 |
|---|---|
| 1-2 | 男女で別々に登録・ログイン、プロフィール保存後の再ログインで保持。`role: admin` の自己申告登録は拒否。誤パスワードは拒否 |
| 3 | 画像アップロード→署名URLで取得（200 / image/png）。他人のフォルダへのアップロード・登録は拒否。未ログインは署名URL発行不可 |
| 4-5 | 検索・絞り込み（エリア・ランク）・詳細。FREE は S/B がロック→SILVER（サンドボックス）で B 解放→運営のデモ利用額付与で利用額ランク A（広い方が適用）。一般ユーザーは利用額付与 RPC を実行不可 |
| 6 | 「自分で選ぶ」ではプロフィール申請→承認後のみ予約申請可。「幅広く」でも自動確定せず、男性は承認不可。承認で同枠の他申請は不成立。重複申請・自分の枠の重複・男性の確定予約との重複・**承認時の競合**をすべてサーバーで拒否。辞退・不正遷移の拒否 |
| 7 | 当事者間のチャット送受信、禁止語の拒否。第三者は RPC でも REST 直接参照でも 0 件・送信不可・直接 INSERT 不可 |
| 8 | 完了で女性の確定報酬（総額=手数料+純額）・XP、男性の確定利用額・XP が増加。女性側に男性の支払額、男性側に女性の報酬は非表示。返金承認で台帳に取消行・利用額が元に戻る |
| 9 | 通報が運営一覧に届く。ブロックで検索非表示・チャット遮断（RLS でも 0 件）。退会申請後は操作不可、運営の匿名化処理後はログイン不可 |
| 10 | 管理 RPC は一般ユーザー不可、内部関数（再計算・決済確定・状態遷移・通知・返金処理）は実行権限なし（42501）。自分のランク・利用額・ロール・決済・プラン・報酬台帳を直接書き換え不可。他人のプロフィール・決済・本人確認・監査ログは参照不可。未ログインは公開設定のみ。運営の非公開審査スコアは本人にも列権限で非公開。管理者は参照可、プラン変更が公開料金に反映され監査ログに記録 |
| 13 | 新規男性登録→本人確認（18歳は拒否）→運営承認→検索→申込→女性承認→チャット→通知→完了→利用額・XP・バッジ反映→履歴 |

## 同時実行（`tests/race-pg.sh`・実 PostgreSQL 16）

同じ男性への時間の重なる 2 件の申請を、2 人の女性が別セッションでほぼ同時に承認。
✅ 先に承認した側のみ `accepted`、もう一方は `BOOKING_CONFLICT`（「この時間帯は既に確定済みの予約と重なっているため承認できません」）で拒否され `requested` のまま。

## 未実施と代替

| 未実施 | 理由 | 代替として実施したこと |
|---|---|---|
| iOS / Android 実機・シミュレータでの操作 | 環境にシミュレータ・実機がない | ネイティブ向け JS バンドルの書き出し成功、Web での全フロー操作、セーフエリア/キーボード対応のコード実装 |
| `supabase start`（公式 Docker スタック）での動作 | Docker イメージの取得がネットワーク制限で失敗 | 同一マイグレーションを PGlite と実 PostgreSQL 16 に適用、supabase-js で Auth/RPC/Storage を互換サーバー経由で検証 |
| Supabase Realtime の配信 | 同上 | `messages` / `notifications` を publication に登録、RLS ポリシーで配信対象を制限する設定を実装。ローカルはポーリングで代替 |
| 本番決済・eKYC | 契約・審査前 | サンドボックス実装と状態遷移・台帳・返金の検証 |
